# 产品文档复审管理规范

本文档说明站点「复审管理」机制的设计原则。页脚在每页展示**负责人、校验范围与日期**；
复审到期只给出「信息需核实」提示，**不会自动撤下任何历史可读内容**。

## 1. 责任与页脚

- 每页页脚三要素：**负责人**、**校验范围（覆盖率与状态）**、**复审日期（公开日期 / 应于）**。
- 负责人离职或小组调整时，只转派**待办任务**；已产生的签收证据保留原签收者，不被覆盖。
- 没有继任负责人时，任务进入「超期 · 无负责人」状态并进入维护者待办，而不是被静默忽略。

## 2. 任务生成：按发布版

- 后台在文档**发布版（release）**生成维护任务，任务携带固定周期（默认 30 天）。
- **固定周期扫描**与**依赖变更触发**两类来源合并到同一发布版的同一个打开任务，
  到期日取两者更早；重复扫描 / 重复触发幂等，不产生重复待办或重复提醒。

## 3. 审阅范围与覆盖图

- 声明范围（示例、接口、截图、章节等）必须全部被审阅项的覆盖图（covers）覆盖，否则发布被拒绝。
- **检查了一处示例不代表整篇已复审**：覆盖率按声明目标统计（如 1/3），不完整就不签收。
- 正文关键块的内容指纹变化，会把引用该块的检查项置回「待重验」并记录变化来源。
- 上游接口 / 素材等依赖变化，同样使相关项待重验，并产生带宽限期的依赖触发任务。

## 4. 签收与公开日期

- 仅当声明范围**全部**由通过的检查项覆盖，且没有失败 / 待办项时，才允许签收。
- **公开日期反映真实完成范围**：等于完整签收的时刻，而不是发布时刻；
  部分失败、部分通过都不会写公开日期。
- 之后若关键变化使已验证结论失效，当前公开日期清空，页面转为「信息需核实」，
  但历史内容、上次完成范围与签收证据都保留可查。

## 5. 到期与提醒

- 周期到期 = 「到期需核实 / 复审超期」提示，**绝不撤回内容**。
- 提醒按「任务 + 站点时区日历日 + 渠道」幂等，提醒任务可安全重跑。
- 维护者视图下，超期项展示**结构化原因**：周期截止、依赖变更、责任交接、检查失败、待重验、无负责人，
  而不只是一个黄色标签。

## 6. 站点时区

- 所有时间以 UTC 存储，周期与到期按**站点时区的日历日**计算；
  切换站点时区（如 `Asia/Shanghai` 与 `America/Los_Angeles`）后，同一发布时刻推导出的到期日会相应变化。
